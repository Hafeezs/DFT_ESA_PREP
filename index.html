PART 1 — ISA‑1 (Units 1 & 2)

1A. One‑mark MCQs (with the reason, not just the key)

Q1. VLSI testing ______

Why Verifies the correctness of hardware. Testing is a post-silicon activity that checks the manufactured chip against the design sent to fab. Verification (design correctness, formal methods) is pre-silicon.

Q2. Test cost is a ______

Why Recurring expenditure. Every die must be put on the ATE and tested, so the cost recurs per-chip for the product's life — unlike a one-time mask/design cost.

Q3. A fault that appears and disappears as a function of time is called ______

Why Intermittent fault. Caused by marginal / temperature- / voltage-dependent defects; hard to catch because it isn't always active. Permanent faults are always present.

Q4. The measure of how easily a node can be set to logic 0 or logic 1 by signals applied to the primary inputs is ______

Why Controllability. Controllability = ease of driving a node from PIs; observability = ease of propagating it to a PO. SCOAP is the algorithm that measures both.

Q5. A phenomenon in which there is a difference between the unintended implemented hardware and its intended design is known as ______

Why Defect. A defect is the physical imperfection (short/open); a fault is its logic-level model; an error is the wrong output produced when the fault is activated.

Q6. Burn-in tests are performed to isolate the ______

Why Both freak failures and infant-mortality failures. Burn-in stresses parts at elevated voltage/temperature to weed out weak devices that would fail early in the field.

Q7. In the D-algorithm, the logic state "D" represents ______

Why D = 1 (good) / 0 (faulty). D ≡ 1/0 and its complement D̄ ≡ 0/1. These two symbols track the difference between the fault-free and faulty machines as it propagates to a PO.

Q8. The number of scan chains in a design is determined in which stage of the scan flow?

Why Scan configuration. It decides chain count, length and clock/edge grouping before stitching. Reordering optimises routing; stitching connects the cells.

Q9. The major advantage of the Muxed-D scan cell is ______

Why Compatibility with single-clock D-FF designs + EDA support. It reuses the existing D-FF plus one MUX, dropping straight into standard synthesis/ATPG flows. (The MUX delay is its drawback, not its advantage.)

Q10. All storage elements are converted into scan cells and combinational ATPG is used for test generation. This is ______

Why Full scan design. Converting every FF turns sequential ATPG into a purely combinational problem — the highest-coverage, highest-overhead option.

Q11. Which of the following statements is TRUE?

Why Pure combinational circuits don't require scan. With no state elements, every internal node is already controllable/observable from PI/PO, so combinational ATPG alone suffices.

Q12. A memory-like structure with a row decoder and column decoder is used to insert the scan chain and combinational ATPG is performed. This scan design is ______

Why Random-access scan design. Each scan cell is addressed like a memory bit via row/column decoders, allowing direct read/write of any cell (high access, high area cost).

Q13. The major disadvantage of the clocked-scan cell technique is ______

Why It needs an extra dedicated shift clock routed everywhere. The clocked-scan cell separates shift and capture using two clocks, so a separate shift clock must be distributed across the chip.

Q14. Scan integrity / chain check is performed to verify ______

Why That the scan chain is wired end-to-end (SI→SO). A flush/chain test shifts a known pattern (e.g. 00110011) through and checks it comes out correctly, before any ATPG patterns are applied.

Q2a. Differentiate between manufacturing test and characterization test.

Aspect Manufacturing Test Characterization Test
Purpose Sort good vs defective dies after fabrication Verify the design is correct and meets all specs
Run on Every chip (production, high volume) A few sample chips (engineering, low volume)
Detects Manufacturing defects — stuck‑at, bridging, opens Design/spec margins; full AC & DC parametric behaviour

Q2b. Generate the test pattern for stuck‑at‑0 and stuck‑at‑1 at primary input C using the Boolean‑difference method.

↓ From the question paper

Circuit: F = (A + B)·C′ + C·D (A,B feed an OR; its output and C′ feed an AND; C,D feed an AND; the two AND outputs feed an OR → F).

Step 1 — Boolean difference of F w.r.t. C: $$\frac{dF}{dC} = F_{C=0} \oplus F_{C=1} = (A+B) \oplus D = AD' + BD' + A'B'D$$

Step 2 — Test for C stuck‑at‑0 (C/0): activate with C = 1 and sensitise: $$C \cdot \frac{dF}{dC} = 1 \;\Rightarrow\; ACD' + BCD' + A'B'CD = 1$$ Test patterns (A B C D):

1 X 1 0
X 1 1 0
0 0 1 1

Step 3 — Test for C stuck‑at‑1 (C/1): activate with C = 0 and sensitise: $$C' \cdot \frac{dF}{dC} = 1 \;\Rightarrow\; AC'D' + BC'D' + A'B'C'D = 1$$ Test patterns (A B C D):

1 X 0 0
X 1 0 0
0 0 0 1

(Any one pattern from each set is a valid test. The Boolean difference dF/dC guarantees the fault effect reaches output F.)

Q2c. Apply the checkpoint theorem to reduce the number of faults.

↓ From the question paper

Circuit: a small multi‑level network; *every line is initially tagged sa0 + sa1 (32 faults total = 16 lines × 2).

Checkpoint theorem: A test set that detects all stuck‑at faults on the primary inputs and fanout branches (the "checkpoints") detects all stuck‑at faults in the entire combinational circuit. So instead of targeting every line, you only target faults at checkpoints.

Procedure & result (as worked in the paper): - Step 1 – Fault collapsing by equivalence/dominance first: brings the count from 32 → 20 faults → collapse ratio = 20/32 = 0.625. - Step 2 – Apply checkpoint theorem (keep only PI + fanout‑branch faults): count drops to 17 → collapse ratio = 17/32 = 0.53.

Takeaway: Checkpoint theorem + collapsing reduces the ATPG fault list to ~53 % of the original, cutting test‑generation effort with no loss of coverage.

Q2d. With a neat diagram, explain the MUX‑based (Muxed‑D) scan cell with waveforms.

↓ From the question paper

↓ From the question paper

Structure: a normal D‑flip‑flop preceded by a 2:1 multiplexer. MUX inputs are DI (functional data) and SI (scan in); the select line is SE (scan enable). MUX output → D of the FF; FF output → Q and to the next cell's SI (forming the scan chain).

        DI ─0┐
             MUX ── D ┌──FF──┐── Q / SO
        SI ─1┘        │  >CK │
   SE ──── sel        └──────┘

Operation (two modes): - SE = 0 → Normal / Capture mode: MUX selects DI; on the rising clock edge the functional data is captured — the cell behaves like an ordinary FF. - SE = 1 → Shift mode: MUX selects SI; each clock pulse shifts data along the scan chain (load test stimulus / unload response).

Waveforms (describe in answer): Show CK as a clock train; SE high during shift, low during capture. During shift, SI values (T₁,T₂,…) appear at Q‑SO one clock later each. During capture (SE low) Q takes the functional value Dₙ on the next edge.

Advantage: single‑clock, EDA‑friendly. Drawback: MUX adds delay to the functional path.

1C. Four‑mark questions

Q4a (1a). Find the pattern using the D‑algorithm to detect stuck‑at‑0 at primary input A.

↓ From the question paper

Circuit: e = A·B (AND); f = e + C (OR); g = D′ (inverter/NAND of D); k combines g; h = f ⊕ (…); output L (NAND of k‑path and h‑path).

D‑algorithm steps:

  1. Fault activation (justify the opposite value): to test A sa0, drive A = 1. Good machine A = 1, faulty machine A = 0 → place D on line A.
  2. Forward implication through e (AND): to propagate D through the AND e = A·B, set the other input B = 1. Then e = D (good 1, faulty 0).
  3. Propagate through f (OR): for D to pass an OR, all other inputs must be non‑controlling = 0, so C = 0 → f = D.
  4. D‑drive to the output: propagate f = D along the path through h toward L. Set the side inputs of the gates on this path to their non‑controlling values so the D reaches L. Working back, the D‑input branch D is set so the g/k side input to the final NAND is the non‑controlling 1 (i.e., choose D so that k = 1). This makes L = D̄ (fault observable at the output).
  5. Consistency / J‑frontier check: all assignments (A = 1, B = 1, C = 0, D = chosen value) are mutually consistent — no conflict.

Test vector: A = 1, B = 1, C = 0, D = (value that sets k = 1) detects A/0; the fault shows as L flipping between good and faulty machines. (Method to state in exam: activate → D‑frontier propagation → justify side inputs to non‑controlling values → consistency. The fault effect = D appears at A, becomes D at e, D at f, then D̄ at L.)

Q4b. Generate the pattern to detect SA1 at node H using the D‑algorithm.

Circuit (from the hint figure): inputs A,B drive an AND → H; H feeds further logic through nodes j, n, P, R, q etc., with two reconvergent paths into a final XOR. A hint notes "the only valid tests require these two paths to be opposite."

Steps: 1. Activate H sa1: drive H = 0 in the good machine (so good 0 / faulty 1 → place D̄ on H). With H = A·B, set A = 0 (or B = 0) to make H = 0; the paper's solution uses A = 0, B = 0 region with appropriate side values. 2. Set up the D‑frontier: push D̄ forward through the gate at j/n. Choose side inputs to their non‑controlling values so the fault effect survives. 3. Reconvergent fanout — use the hint: the two reconverging paths feed an XOR. For the fault effect to be observable at the XOR output, the two path values must be opposite (one carries the fault‑effect D̄, the other a fixed complementary constant). That is the "only valid test" condition. 4. Justify all side inputs (C, F, etc.) to satisfy both the propagation along the chosen path and the "opposite" requirement at the reconvergent XOR; resolve the noted FAIL branch by switching the choice at the decision point (D‑algorithm backtracking). 5. Consistency check → the surviving assignment is the test.

Key learning point: this circuit has reconvergent fanout, so a naive single‑path sensitisation fails; the D‑algorithm's multiple‑path (decision/backtrack) capability is required, and the valid test is the one that makes the two reconverging paths carry opposite values into the XOR.

Q1b. With neat diagrams, explain Full / Partial / Random‑access scan design.

↓ From the question paper

1. Full‑scan design

— every storage element is converted to a scan cell and stitched into chains. Test generation reduces to combinational ATPG (FFs become controllable PIs / observable POs in shift mode). - ✔ Highest fault coverage, simplest ATPG, best automation. - ✘ Maximum area (every FF gets a MUX) and routing overhead; performance penalty.

2. Partial‑scan design

— only a subset of FFs is made scannable (chosen to break feedback loops / improve testability). Sequential ATPG is typically needed for the remaining non‑scan FFs. - ✔ Lower area/timing overhead than full scan. - ✘ Lower coverage, harder (sequential) ATPG.

3. Random‑access scan design

— scan cells are arranged like a memory array with row & column decoders; any individual cell can be directly addressed (read/written) rather than shifted through a serial chain. - ✔ Direct access → very high controllability/observability, useful for diagnosis and analog/mixed nodes; no long shift sequences. - ✘ Large area for the address decoders and addressing logic.

(Draw: full‑scan = combinational cloud + serial chain of SFFs with SI/SE/SO; partial‑scan = same but only some FFs scanned; random‑access = grid of cells with row/column address decoders and a single scan data line.)

Q1a. LFSR signature analysis.

↓ From the question paper

Question: The scan output stream is 0101 0001 and is fed into an LFSR for compaction with primitive polynomial x⁵ + x³ + x + 1. Find the signature (with LFSR circuit and the calculation table).

Circuit: a 5‑stage LFSR (X₀…X₄) with XOR taps placed according to the polynomial x⁵ + x³ + x + 1 (feedback into stages corresponding to the x³, x¹, x⁰ terms). The serial scan stream is XOR‑ed into the input — this makes it a single‑input signature register (SISR).

Method (polynomial division): the signature = (data‑stream polynomial) mod (characteristic polynomial). - Data stream 0101 0001 → data polynomial M(x) = x⁷ + x³ + x. - Divide M(x) by P(x) = x⁵ + x³ + x + 1 using mod‑2 (XOR) arithmetic. - Remainder after division = 1 + x² + x³.

Signature (final LFSR contents X₀X₁X₂X₃X₄): $$\boxed{\text{Signature} = 1 + x^{2} + x^{3} \;\equiv\; (X_0X_1X_2X_3X_4) = 1\,0\,1\,1\,0}$$

How to present in exam: draw the 5‑bit LFSR with the taps, make a table with columns Input, X₀, X₁, X₂, X₃, X₄, start from initial state 00000, and step one row per input bit (shift + XOR the feedback + the incoming data bit). The register contents after the last bit = the signature = 10110 (= 1 + x² + x³). A different/golden signature → fault detected (subject to aliasing).

✅ X‑Compactor (X‑tolerant response compactor). - It is a combinational compactor of scan‑chain outputs, designed using the X‑compact technique — tolerant of unknown (X) values in the response. - Represented by a binary X‑compact matrix (n rows = scan chains, k columns = compactor outputs); shown here as an 8 → 5 compactor (8 scan outputs into 5 ATE channels). - Two aliasing mechanisms in sequential compactors are error masking and error cancellation; because the X‑compactor is purely combinational it only suffers error masking, which the X‑compact matrix design rules are built to minimise. - Purpose: compress many scan outputs into few ATE pins while still detecting errors even when some bits are X.

✅ Boundary‑Scan Cell (BSC) — the IEEE 1149.1 (JTAG) boundary cell. - Can act as an input cell (IN tied to a chip input pad) or output cell (OUT tied to an output pad). - R1 = capture/shift flip‑flop, R2 = update flip‑flop (holds a stable value while R1 shifts). - Mode = 0 (Normal): data passes directly IN → OUT; the cell is transparent to functional logic. - Mode = 1 (Test): OUT is driven by the R2 flip‑flop (the shifted‑in test value). - Operation is controlled by three TAP‑controller signals: ClockDR, ShiftDR, UpdateDR (capture → shift → update). From the transfer‑curve graph, the deviations from the ideal straight line are: - Hysteresis error (HE ≈ 2 LSB): transfer curve follows one path as input rises and a different path as it falls; magnitude = max deviation between the two, in LSB. - Temperature‑dependent error (≈ 4 LSB @ 75 °C): gain/error grows as temperature rises (performance degrades with temperature); often quoted as %. - Load‑dependent error (≈ 5.5 LSB @ 500 Ω): improper output‑driver impedance; for a voltage‑mode DAC, too‑large output impedance under a small load resistance reduces gain. - Resolution error: inability to resolve small input variations; for an n‑bit ADC resolution is 2ⁿ, but noise/distortion lower the effective number of bits (ENOB).

2C. One‑mark MCQs (Q7–Q19)

Q7. The value set (S0, S1, U0, U1, XX) is a five-valued algebra used in the pattern generation of the ______

Why Robust delay test. The five-valued algebra tracks steady (S0/S1) and transitioning (U0/U1) values along a path so the test holds regardless of other path delays.

Q8. The cellular-automata cell with XOR feedback from neighbours Qk−1, Qk+1 (and itself) into a D-FF is known as a ______

Why Type-150 cell. Rule 90 = Qk−1 ⊕ Qk+1 (neighbours only); rule 150 = Qk−1 ⊕ Qk ⊕ Qk+1 — it also XORs the cell's own state.

Q9. A response-compaction method in which the number of 0→1 and 1→0 transitions at the primary outputs is counted to create the signature is ______

Why Transition-count-based response compaction. The compactor counts output transitions; that count is the signature, compared against the fault-free count (it is compaction — lossy — not compression).

Q10. The X-Compact test-compression scheme performs ______

Why Space compression. X-Compact is a combinational compactor that maps many scan outputs to few channels in the space domain (a MISR is time compression).

Q11. A test that guarantees to detect a path-delay fault, only when no other path-delay fault is present in the circuit, is called ______

Why Non-robust test for that path. It detects the target only if no other delay fault interferes (off-path inputs may glitch). A robust test detects it regardless of other delays.

Q12. A Boolean polynomial that cannot be factored, useful in designing the BIST, is known as a ______

Why Irreducible polynomial. It cannot be factored. A primitive polynomial is a special irreducible one that yields a maximal-length (2ⁿ−1) LFSR sequence.

Q13. Built-in Self-Repair (BISR) automatically identifies and fixes faults in memory blocks. The principle of BISR is ______

Why It uses spare rows & columns to replace the defective addresses. Redundant elements built into the array are swapped in for failing cells, preserving the full memory capacity.

Q14. The fastest ADC is the ______

Why Flash ADC. Parallel comparators give a single-step conversion — fastest, but most area- and power-hungry (needs 2ⁿ−1 comparators).

Q15. Resetting of the boundary-scan chain is performed by the ______

Why JTAG TAP controller. Its Test-Logic-Reset state (via the TRST pin or five TMS = 1 clocks) resets the boundary-scan logic.

Q16. The IEEE 1500 standard is useful in ______

Why Testing core-based designs. 1500 defines a standard wrapper (WIR + wrapper cells + WBY) so embedded/reusable cores can be tested independently in an SoC.

Q17. IJTAG (Internal JTAG) / IEEE 1687 is ______

Why Required to access on-chip instruments. It provides a reconfigurable scan network (SIBs/segments, described by ICL and operated by PDL) to reach embedded instruments.

Q18. Verilog-A or Verilog-AMS is required for ______

Why Modelling and test generation for analog designs. Verilog-A (analog) and Verilog-AMS (mixed) describe analog blocks behaviourally for fast mixed-signal simulation and analog test development.

Q19. The deviation between the ideal input threshold value and the measured threshold level of a certain output code in an ADC is ______

Why Integral Non-Linearity (INL). INL = cumulative deviation of a code threshold from the ideal line; DNL = error in a single code's width.

PART 3 — PRACTICE QUESTIONS (full answers)

Unit 1 — Testing Fundamentals

1. Difference between Verification and Test.

Verification is pre‑silicon: it checks that the design (RTL/netlist) is functionally correct vs the specification (simulation, formal, emulation). Test is post‑silicon: it checks that each manufactured chip is defect‑free vs the design that went to fab, using ATE and test patterns. Verification is one‑time per design; test recurs per chip.

2. Define: ATE, Wafer, Die, Wafer Probing, Packaging.

- ATE (Automatic Test Equipment): machine that applies test patterns to a chip and compares responses against expected values. - Wafer: thin silicon disc on which many identical dies are fabricated together. - Die: a single chip (one copy of the design) on the wafer. - Wafer probing: testing each die while still on the wafer using probe needles, to discard bad dies before packaging. - Packaging: encapsulating a good die into a protective package with pins/balls for board mounting.

3. Types of tests in VLSI testing.

Manufacturing/production test, characterization (design verification) test, burn‑in (reliability) test, evaluation/qualification test, parametric (DC/AC) test, functional test, and structural test (scan/ATPG, BIST).

4. Manufacturing / Evaluation / Characterization / Burn‑in test.

- Manufacturing test: per‑chip pass/fail screen for fabrication defects. - Evaluation (qualification) test: thorough testing of first silicon to qualify the product before volume. - Characterization test: exhaustive AC/DC measurement on samples to confirm the design meets all specs and find margins. - Burn‑in test: elevated voltage/temperature stress to precipitate early‑life (infant‑mortality) failures before shipping.

5. List the characterization tests.

Functional verification, AC parametric (timing — setup/hold, propagation delay, Fmax), DC parametric (VIL/VIH, IOL/IOH, leakage), Schmoo plots (voltage vs frequency), and internal‑node probing.

6. Parametric vs Functional tests.

Parametric tests measure electrical quantities — voltages, currents, timing — independent of logic function (DC: leakage, thresholds; AC: speed). Functional tests check the logical behaviour — does the circuit produce correct outputs for given inputs.

7. Describe the ATPG flow (with sketch).

Read netlist + library → build fault list (collapse faults) → DRC (design‑rule / scan‑chain checks) → target a fault → generate a pattern (D‑algorithm/PODEM) → fault simulation to drop all faults the pattern detects → repeat until coverage target met → compact patterns → write patterns (STIL/WGL) + coverage report.

8. Importance of test‑data analysis.

Test‑data (yield, failing patterns, failing bins) analysis reveals systematic vs random defects, drives yield improvement and diagnosis, helps tune the test program (reduce overkill/escape), and feeds back to design/process — directly impacting cost and quality.

9. How test economics drive profits.

Test cost is recurring per‑chip; DFT lowers test time, ATE pin count and pattern volume, raising throughput. Good test maximises yield of good parts and minimises test escapes (field returns). Lower test cost + higher quality + faster time‑to‑market = higher margin/profit.

10. Controllability and Observability.

- Controllability: ease of setting an internal node to a desired logic value from the primary inputs. - Observability: ease of propagating an internal node's value to a primary output. DFT (scan) improves both.

11. Stuck‑at, bridge, delay fault.

- Stuck‑at fault: a line permanently fixed at 0 (sa0) or 1 (sa1). - Bridge fault: unintended short between two lines (wired‑AND/wired‑OR or dominant behaviour). - Delay fault: circuit is logically correct but a path is too slow (transition/path‑delay), failing at speed.

12. Defect vs Error vs Fault.

Defect = physical imperfection in silicon. Fault = abstract/logic model of that defect. Error = the incorrect output value observed when a fault is activated. (Defect → modeled as Fault → manifests as Error.)

13. Fault equivalence, Fault collapsing.

- Fault equivalence: two faults are equivalent if no test can distinguish them (identical output behaviour for all inputs) → keep only one. - Fault collapsing: reducing the fault list using equivalence and dominance relations, lowering ATPG effort with no coverage loss.

14. Checkpoint theorem.

A test set that detects all stuck‑at faults on the primary inputs and fanout branches (the checkpoints) detects all stuck‑at faults in the whole combinational circuit. It lets ATPG target only checkpoint faults → far fewer faults to process.

Unit 2 — Test Pattern Generation

1. Purpose of digital testing.

To detect/locate manufacturing defects in digital circuits so only defect‑free chips ship — ensuring quality and reliability at minimum cost.

2. Fault simulation — definition, goals, outputs.

Fault simulation applies test patterns to fault‑injected copies of the circuit to see which faults each pattern detects. - Goals: measure fault coverage of a pattern set, drop detected faults, grade/compact tests. - Outputs: list of detected/undetected faults, fault coverage %, and per‑pattern detection data.

3. Serial fault simulation.

Simulate the fault‑free circuit once to get reference outputs; then inject one fault at a time, simulate the whole pattern set, and compare to reference. Simple but slow (one full simulation per fault).

4. Fault coverage / test coverage.

$$\text{Fault Coverage} = \frac{\text{detected faults}}{\text{total faults}}, \quad \text{Test Coverage} = \frac{\text{detected}}{\text{detectable (testable) faults}}$$ Test coverage excludes untestable/undetectable faults from the denominator.

5. Parallel vs Deductive vs Concurrent fault simulation.

- Parallel: pack many faulty machines into machine words and simulate in parallel (bitwise) — fast for few faults per pass. - Deductive: carry a list of faults detectable at each line; deduce fault propagation in one pass — memory‑heavy. - Concurrent: simulate only the parts of faulty circuits that differ from the good circuit (event‑driven on divergent gates) — generally the most efficient.

6. Elements of fault simulation.

Good‑circuit simulator + fault list (collapsed) + fault‑injection mechanism + comparison logic (faulty vs good outputs) + fault‑dropping bookkeeping + coverage reporter.

7. Fault dropping and fault sampling.

- Fault dropping: once a fault is detected, remove it from the active list to save simulation effort. - Fault sampling: simulate a random subset of faults to estimate coverage quickly for large designs.

8. Serial fault‑simulation algorithm — advantages/disadvantages.

Algorithm: simulate good circuit → for each fault: inject, simulate all vectors, compare, mark detected. ✔ Simple, handles any fault model, low memory. ✘ Very slow (time ∝ #faults × #vectors).

9. ATPG process (flowchart).

Pick target fault → activate it (set fault site to opposite value, place D/D̄) → propagate D‑frontier to a PO → justify all required line values back to PIs (J‑frontier) → if conflict, backtrack → fault‑simulate the vector to drop other detected faults → repeat until coverage met.

10. Path sensitisation / forward driving.

Driving the fault effect forward from the fault site toward a PO by setting the side inputs of gates along the path to their non‑controlling values (0 for OR/NOR, 1 for AND/NAND) so the D/D̄ propagates unchanged.

11. Boolean‑difference method.

For fault on line x, compute $\frac{dF}{dx}=F_{x=0}\oplus F_{x=1}$. A test for x sa0 satisfies $x\cdot\frac{dF}{dx}=1$; for x sa1, $x'\cdot\frac{dF}{dx}=1$. Solving gives all detecting input patterns. (Algebraic, exact, but expensive for large circuits.)

12. D‑algorithm (flowchart).

Define a fault → set fault site to D/D̄ (activation) → choose a propagation path, advance the D‑frontier toward a PO (forward implication) → justify the required values back to PIs via the J‑frontier (backward implication) → on conflict, backtrack to the last decision → success when a D/D̄ reaches a PO and all assignments are consistent. Uses 5‑valued algebra {0,1,X,D,D̄}.

13. D‑frontier and J‑frontier.

- D‑frontier: gates whose output is still X but which have D or D̄ on at least one input (candidates for fault propagation). - J‑frontier: gates whose output value is set but whose inputs are not yet justified (need backward justification).

14. Where the D‑algorithm fails (example).

In circuits with reconvergent fanout, the D‑algorithm can spend huge effort backtracking because internal decisions conflict at the reconvergence point — it makes choices on internal lines without knowing they're inconsistent until late (e.g., ECAT/XOR‑reconvergent circuits).

15. How PODEM overcomes D‑algorithm's failure.

PODEM only makes decisions on primary inputs (objective → backtrace to a PI → imply forward). Because the search space is just the PIs and every assignment is immediately implied, there are no inconsistent internal choices → far less backtracking on reconvergent circuits.

16. Random vs deterministic vectors; LFSR for random patterns.

Random vectors are cheap to generate (no ATPG) and catch many easy faults quickly, good for BIST. Hard faults still need deterministic ATPG. An LFSR (shift register with XOR feedback from a primitive polynomial) cycles through a pseudo‑random maximal‑length (2ⁿ−1) sequence, providing on‑chip random test patterns.

Unit 3 — DFT & BIST

1. Delay fault model vs stuck‑at.

A delay fault means the logic value is correct but arrives too late (timing failure) — must be tested at‑speed with a two‑vector pattern (launch + capture). A stuck‑at fault is a static wrong value, testable with a single vector at any speed.

2. Non‑robust vs robust path‑delay test.

A robust test detects the target path's delay fault regardless of delays on other paths (glitch‑free, off‑path inputs held at non‑controlling steady values). A non‑robust test detects it only if no other path‑delay fault is present (off‑path inputs may glitch).

3. Five‑value algebra for path‑delay ATPG.

Uses {S0, S1, U0, U1, XX} — S0/S1 = steady 0/1 (stable both vectors), U0/U1 = a transition ending in 0/1, XX = unknown — to track the two‑vector launch→capture behaviour along the path.

4. Definitions.

- Single‑input‑change (SIC) test: only one PI changes between the two vectors. - Validatable non‑robust test: a non‑robust test whose correctness can be guaranteed if certain other paths are also tested. - Untestable path‑delay fault: no two‑vector pattern can launch and propagate a transition along that path.

5. Transition delay test.

Models a slow‑to‑rise / slow‑to‑fall gate. Two vectors: V1 launches the transition, V2 (one at‑speed clock later) captures. If the path is too slow the wrong value is captured. (Two common methods: launch‑on‑shift / launch‑on‑capture.)

6. Scan‑path testing — importance.

Scan reconfigures FFs into a shift register in test mode, making every FF directly controllable and observable. This converts hard sequential ATPG into easy combinational ATPG, giving high coverage and easy diagnosis.

7. Mux‑based vs LSSD vs Clocked scan cell.

- Muxed‑D: ✔ single clock, EDA‑friendly; ✘ MUX delay on functional path. - LSSD (Level‑Sensitive Scan Design): ✔ latch‑based, race‑free using non‑overlapping clocks; ✘ extra clocks/area, more routing. - Clocked scan cell: ✔ no MUX in data path (no functional‑path delay); ✘ needs an extra dedicated shift clock routed everywhere.

8. Full / Partial / Random‑access scan design.

(See ISA‑1 Q1b — identical answer.) Full = all FFs scanned, combinational ATPG; Partial = subset scanned, sequential ATPG; Random‑access = memory‑addressed cells via row/column decoders.

9. Scan design rules, violations, solutions.

Rules: no uncontrollable clocks/resets, no combinational feedback loops, no gated/internally generated clocks driving scan FFs, set/reset must be off in shift. Violations: combinational loops, clock‑as‑data, uncontrolled async set/reset. Solutions: break loops, make clocks/resets controllable from a PI in test mode, bypass/fix gated clocks.

10. Scan reordering and scan stitching.

Stitching = connecting scan cells into chains (SO→SI). Reordering = choosing the cell order within a chain after placement to minimise wire length/congestion (physically aware ordering) while preserving chain integrity.

11. BIST terms.

- BILBO (Built‑In Logic Block Observer): a multi‑mode register that works as normal register / TPG (LFSR) / MISR / scan. - STUMPS (Self‑Test Using MISR & Parallel SRSG): architecture with a PRPG feeding multiple scan chains, responses compacted by a MISR. - MISR (Multiple‑Input Signature Register): LFSR with multiple XOR inputs → compacts parallel responses into a signature. - Primitive polynomial: polynomial giving a maximal‑length (2ⁿ−1) LFSR sequence. - Concurrent testing: testing performed during normal operation (online), e.g., with coding/duplication.

Unit 4 — Test Compression, Memory Test, BIST, Delay

Test Compression

1. Importance of test compression; vs BIST.

Compression shrinks ATPG pattern volume & test time by feeding compressed stimuli from few ATE channels (decompressor on‑chip) and compacting responses (compactor). Unlike BIST (patterns generated on‑chip, pseudo‑random, self‑contained), compression still uses ATE‑supplied deterministic patterns — just compressed.

2. Dictionary‑code test compression.

Store a dictionary of frequently‑used test slices; transmit short codewords (indices) instead of full vectors; an on‑chip decoder looks up the dictionary to regenerate the full pattern.

3. LFSR‑based decompression schemes.

Static reseeding, dynamic (continuous‑flow) reseeding, combinational linear decompressor (XOR network / phase shifter), and ring‑generator‑based decompressors.

4. Why the Illinois scheme is widely adopted.

It combines an LFSR with selective reseeding/XOR injection that achieves high encoding efficiency with few specified bits, handling don't‑cares well — giving high compression with low overhead, hence industry adoption.

5. LFSR‑based linear decompression (sketch).

A continuous‑flow LFSR (ring generator) is loaded/injected with seed bits from the ATE channels; its outputs pass through a phase shifter (XOR network) to drive many scan chains. Each scan‑in bit is a linear (XOR) combination of free variables → solved as linear equations to encode each test cube.

6. Time‑based vs space‑based compaction.

Space compaction (combinational, e.g., XOR tree / X‑compactor): many scan outputs → few channels in one cycle. Time compaction (sequential, e.g., MISR): accumulates responses over many cycles into one signature.

7. X‑Compact for 8:5 — matrix.

X‑compact maps n=8 scan chains to k=5 outputs via a binary X‑compact matrix where each scan chain (row) connects to a unique combination of outputs (so single errors are observable and X's are tolerated). Example 8×5 matrix has 8 distinct, odd‑weight rows; each output Outⱼ = XOR of the chains with a '1' in column j. (Draw the XOR tree: each of 8 SC feeds ≥2 of the 5 outputs.)

8. X‑blocking vs X‑masking.

X‑blocking (X‑bounding): fix X‑sources at the source (logic/DFT) so they never reach the compactor. X‑masking: gate/mask the X‑carrying scan cells at the compactor input (using mask logic + control bits) so only clean bits are compacted.

9. Cadence OPMISR+ architecture.

On‑chip XOR‑based spreader decompresses ATE stimulus to scan chains; responses compacted by an MISR with X‑masking logic (OPMISR = On‑Product MISR). Provides space+time compaction with X‑handling, integrated in the Cadence flow.

10. Mentor (Siemens) EDT architecture.

Embedded Deterministic Test: a ring‑generator + phase shifter decompressor expands a few EDT channels into many scan chains; a compactor (XOR + X‑masking) reduces responses. Achieves 10–100× compression; this is the Tessent flow you use in the course.

Memory Test

1. Test‑time complexity of direct memory testing.

Exhaustively writing/reading all states is O(2ⁿ) for an n‑bit memory — infeasible. March tests reduce this to O(N) (N = number of cells).

2. Permanent vs non‑permanent memory faults.

Permanent: always present — stuck‑at, transition, coupling, address‑decoder faults. Non‑permanent: transient/intermittent — soft errors (radiation), data‑retention, timing‑dependent faults.

3. SAF, TF, CF, NSPF.

- SAF (Stuck‑At Fault): cell stuck at 0 or 1. - TF (Transition Fault): cell fails to make a 0→1 or 1→0 transition. - CF (Coupling Fault): a write to one cell wrongly affects another cell. - NPSF (Neighborhood Pattern‑Sensitive Fault): a cell's behaviour depends on the pattern in its neighbouring cells.

4. Coupling‑fault types.

Inversion CF: a transition in the aggressor inverts the victim. Idempotent CF: a transition forces the victim to a fixed 0 or 1. Dynamic CF: caused by a read/write operation on the aggressor. Bridging fault: short between two cells/lines (AND/OR bridging).

5. Active vs Passive NPSF.

Active NPSF: the victim changes when the neighbourhood pattern changes. Passive NPSF: the victim cannot be changed while a certain neighbourhood pattern is present.

6. Type‑I vs Type‑II NPSF.

Distinguished by neighbourhood definition — Type‑I considers the base cell + its 4 direct (N,S,E,W) neighbours; Type‑II considers a larger neighbourhood (incl. diagonals), giving more thorough but longer tests.

7. March tests.

A March test = a sequence of March elements, each a series of read/write operations applied to every cell in a fixed address order (↑ ascending, ↓ descending, ↕ either). E.g., MATS+, March C‑, March B. They detect SAF/TF/AF/CF in linear O(N) time. (March C‑: {↕(w0); ↑(r0,w1); ↑(r1,w0); ↓(r0,w1); ↓(r1,w0); ↕(r0)}.)

8. Original vs Inverse LFSR in Memory BIST.

A normal LFSR generates pseudo‑random addresses/data; an inverse LFSR runs the sequence in reverse order, used to generate descending address sequences (needed by March elements) or to walk the address space the opposite way — together they give the up/down address ordering March tests require.

Built‑In Self‑Test

1. BILBO, Irreducible polynomial, Non‑concurrent testing.

BILBO = reconfigurable register (normal/LFSR‑TPG/MISR/scan). Irreducible polynomial = cannot be factored. Non‑concurrent testing = test runs only when the system is offline (not during normal operation).

2. Cellular‑automata test‑pattern generation.

A 1‑D array of cells, each a FF whose next state = XOR of itself and/or neighbours per a rule (e.g., rule 90 = Q_{k−1}⊕Q_{k+1}; rule 150 = Q_{k−1}⊕Q_k⊕Q_{k+1}). Mixing rule‑90 and rule‑150 cells gives high‑quality, low‑correlation pseudo‑random patterns with good locality (better for BIST than a plain LFSR). (Show truth table for each rule + the gate realisation.)

3. BIST compaction terms.

Aliasing: a faulty response produces the same signature as the good one (escape). Compaction: reducing a long response to a short signature (lossy). Compression: lossless size reduction. Signature: the final compacted value compared against the golden value.

4. Transition‑count response compaction.

The compactor counts the number of output transitions (0→1 and 1→0) over the test; the count is the signature, compared to the fault‑free count. Simple, but has aliasing when a fault preserves the transition count.

Delay Test

1. Path‑delay vs transition‑delay test.

Path‑delay targets the cumulative delay of a specific path (huge number of paths). Transition‑delay targets a slow gate/node (slow‑to‑rise/fall) — far fewer faults, more scalable, hence widely used.

2. Necessity of at‑speed tests.

Many timing defects only fail at the rated clock frequency; slow‑speed structural tests miss them. At‑speed tests apply launch+capture at functional speed to catch small/resistive delay defects.

3. Robust vs non‑robust delay test.

Robust: detects the fault independent of other delays (off‑path inputs steady at non‑controlling values, hazard‑free). Non‑robust: valid only if no other delay fault interferes (off‑path signals may glitch).

4. Delay‑test methodologies.

Launch‑on‑Shift (LOS / skewed‑load): last shift pulse launches the transition. Launch‑on‑Capture (LOC / broadside): the functional capture pulse launches it. Plus enhanced‑scan (stores two independent vectors per cell). LOC needs no fast scan‑enable; LOS gives higher coverage but needs at‑speed SE.

PART 4 — ASSIGNMENT (full answers)

Test Standards

1. IEEE 1149.1 (JTAG) test architecture and operations.

JTAG adds a boundary‑scan register (a chain of boundary‑scan cells at every I/O pin) plus a small control infrastructure: - TAP (Test Access Port): 4 (+1 optional) pins — TCK (clock), TMS (mode select), TDI (data in), TDO (data out), TRST (optional reset). - TAP controller: a 16‑state FSM driven by TMS that sequences Capture → Shift → Update for the DR and IR. - Instruction Register (IR): selects which data register is between TDI/TDO. - Data registers: boundary‑scan register, BYPASS (1‑bit), IDCODE, optional user registers. - Mandatory instructions: BYPASS, SAMPLE/PRELOAD, EXTEST (+ optional INTEST, IDCODE, etc.). Operation: EXTEST drives/observes board interconnects via the boundary cells (board‑level interconnect test); SAMPLE/PRELOAD snapshots pin values; BYPASS shortens the chain through a 1‑bit register. (Draw: chip with boundary cells around the core, TAP controller, IR & DR multiplexed to TDO.)*

2. Necessity of IEEE 1500 (SoC test standard).

1149.1 is for chip/board pins, not embedded cores. IEEE 1500 defines a standard core test wrapper (WIR + wrapper boundary cells + WBY) so that third‑party/reusable cores can be tested independently in an SoC — isolating a core for inward (core) and outward (interconnect) test, enabling plug‑and‑play core test reuse.

3. How scan & BIST work with boundary scan / JTAG.

JTAG provides the access mechanism: private JTAG instructions select internal test modes. Through the TAP, you can load BIST control, start Logic/Memory BIST, and read back the BIST signature, and you can access internal scan chains (e.g., via a test‑mode instruction that connects TDI/TDO to the scan‑in/scan‑out). So boundary scan = the standardized doorway; scan and BIST = the engines reached through it. (Draw: TAP → instruction decode → enables internal scan chains and BIST controller; signature shifted out on TDO.)

4. Necessity of IEEE 1687 (IJTAG, on‑chip instruments).

Modern SoCs have many embedded instruments (BIST engines, sensors, trim, monitors). 1149.1's flat chain doesn't scale. IEEE 1687 (IJTAG) defines a reconfigurable scan network using SIBs (Segment Insertion Bits) so instruments can be dynamically included/excluded from the active path, with ICL (network description) and PDL (procedure language) for portable, plug‑and‑play instrument access.

Analog Test

1. Importance of Verilog‑A / Verilog‑AMS.

Verilog‑A (analog) and Verilog‑AMS (mixed analog+digital) let you model analog blocks behaviourally, enabling fast mixed‑signal simulation, top‑level verification, and analog test‑stimulus/response generation without slow transistor‑level SPICE for the whole chip.

2. Waveform‑oriented testing.

Instead of pass/fail on static levels, the test applies a known analog waveform (sine, ramp, chirp…) and captures the output waveform, then computes parameters (gain, THD, SNR, INL/DNL via DSP/FFT). Used for ADC/DAC/PLL characterization.

3. Chirp signal, step‑in‑frequency, step‑in‑amplitude.

- Chirp: a sine whose frequency sweeps continuously with time — exercises a wide band quickly (frequency‑response test). - Step in frequency: discrete jumps in input frequency (measure response per frequency point). - Step in amplitude: discrete jumps in input amplitude (measure linearity/gain vs level). (Draw the three waveforms.)

4. CMRR and PSRR (with equations).

- CMRR (Common‑Mode Rejection Ratio): ability to reject signals common to both inputs. $$\text{CMRR} = 20\log_{10}\frac{A_{d}}{A_{cm}}\ \text{dB}$$ (A_d = differential gain, A_cm = common‑mode gain). - PSRR (Power‑Supply Rejection Ratio): ability to reject supply variation. $$\text{PSRR} = 20\log_{10}\frac{\Delta V_{supply}}{\Delta V_{out}}\ \text{dB}.$$ Higher dB = better rejection.

5. ADC transfer characteristic curve.

Plot of digital output code vs analog input. The ideal curve is a uniform staircase, each tread = 1 LSB wide; the dotted ideal straight line runs through the code midpoints. Deviations of the code transition thresholds from this line define offset, gain, DNL and INL errors. (Draw staircase + ideal line; mark 1‑LSB step.)

6. Sample‑and‑Hold (S/H) circuit; why important.

A switch + hold capacitor + buffer: it samples the input when the switch closes and holds that voltage constant on the capacitor while the ADC converts. Importance: without S/H, a changing input during conversion would corrupt the result; S/H freezes the input, guaranteeing the ADC quantizes a stable value (essential for fast/SAR/pipeline ADCs). (Draw: switch → C_hold → unity buffer; sample vs hold phases.)

7. R‑2R ladder DAC.

A resistor network using only two values (R and 2R). Each bit switches a 2R leg between Vref and ground; the ladder performs binary‑weighted current/voltage summation so V_out ∝ digital input. ✔ Only two resistor values → easy matching/integration; scalable. (Draw the ladder with bit switches and op‑amp summer.)

8. Flash vs Pipelined vs Sigma‑Delta ADC.

Flash Pipelined Sigma‑Delta (ΣΔ)
Speed Fastest (1 step) High Low (oversampled)
Resolution Low (≤8b) Medium‑high (10–14b) Very high (16–24b)
Hardware 2ⁿ−1 comparators (huge) Stages of low‑res ADC+amp 1‑bit modulator + digital filter
Use RF/very fast Video/comms Audio/precision/sensors

9. ADC error definitions.

- Offset error: horizontal shift of the whole transfer curve (1st transition ≠ ideal 1st). - Gain error: slope error of the transfer curve (after removing offset) → wrong full‑scale. - INL (Integral Non‑Linearity): max deviation of a code transition from the ideal straight line (= cumulative DNL). - DNL (Differential Non‑Linearity): deviation of each code width from 1 LSB; DNL ≤ −1 ⇒ missing code. - Hysteresis error: output depends on whether the input is rising or falling (curve traces different paths up vs down).
